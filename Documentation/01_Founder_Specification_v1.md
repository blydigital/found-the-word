**constitution of the product**



Founder Specification

1\. Mission

Mission



Help people find the exact word they're trying to remember.



Vision



Build the best tool on the internet for recovering words from meaning.



When someone knows the idea they want to express but cannot recall the word, Found the Word should consistently produce the reaction:



"YES! That's exactly the word I was thinking of."



Success Metric



North Star Metric:



Percentage of searches where users click



✅ That's it.



Every feature should increase this metric.



2\. Product Philosophy



Found the Word is not:



a thesaurus

a dictionary

a chatbot

a writing assistant

an AI wrapper



It is a semantic retrieval engine.



The user knows the concept.



They cannot recall the word.



Our job is to retrieve the best-fitting word.



We optimize for:



precision

correctness

clarity

confidence



Not:



creativity

verbosity

entertainment

3\. Core User Problem



The user is experiencing lexical recall failure.



Examples:



"Word for intentionally rude."



"Blue with gray in it."



"Gymnastics hold hanging from a bar."



"Word meaning pretending to care."



The user often knows:



meaning

tone

context



They simply cannot remember the word.



4\. Product Promise



Describe what you mean.



We'll help you find the exact word.



5\. MVP



The MVP contains exactly one page.



One search box.



One search button.



One response.



Response contains:



Best word

Confidence

Explanation

Three alternatives

Why they differ

👍 That's it

👎 Not quite



Nothing else.



6\. Interaction Philosophy



Search first.



Conversation second.



The application should never ask unnecessary questions.



If confidence is high:



Return the answer immediately.



Only ask follow-up questions when confidence is low.



7\. UI Philosophy



Minimal.



Quiet.



Professional.



No flashy animations.



No avatars.



No "AI assistant."



The interface should feel closer to Google or Dictionary.com than ChatGPT.



The page should initially contain only:



What's the Word?



Describe the word you're trying to remember.



\[\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_\_]



Search

8\. Technical Philosophy



Prefer simplicity.



Avoid premature optimization.



Avoid unnecessary dependencies.



Prefer readability over cleverness.



Build only what improves the product.



9\. AI Philosophy



The AI is invisible.



Users should not think:



"I'm talking to ChatGPT."



They should think:



"This website somehow knew the exact word."



10\. Search Philosophy



Always optimize for:



best-fitting word



NOT



most common word.



When possible:



Explain why the chosen word fits better than the alternatives.



11\. Product Personality



The application should feel like:



A well-read librarian.



Not:



A friendly chatbot.



Not:



A comedian.



Not:



A tutor.



Responses should be calm.



Confident.



Professional.



12\. What We Are NOT Building



No accounts.



No subscriptions.



No communities.



No forums.



No dictionaries.



No articles.



No general-purpose AI chat interface. Guided refinement is allowed when needed to identify the word.



No SEO pages.



No browser extension.



No mobile app.



No gamification.



No achievements.



No learning mode.



Those belong in Version 2+, if ever.



13\. Writing Philosophy



The writing should be timeless, professional, and understated.



Avoid language that feels like it was generated by AI or follows temporary internet writing trends.



Avoid:



Excessive enthusiasm

Buzzwords

Marketing hype

Corporate jargon

Emojis (except where intentionally used for simple feedback such as 👍 and 👎)

Em dashes as a stylistic crutch

Unnecessarily long explanations



Prefer:



Short, direct sentences.

Plain English.

Precise vocabulary.

Confidence without arrogance.

Clarity over cleverness.



The writing should feel like it was produced by an experienced editor or lexicographer rather than an AI assistant.



14\. Product Rule



When deciding between two implementations, choose the one that better helps the user recover the exact word they are trying to remember.



Not the one that is:



more impressive

more technically sophisticated

more AI-driven

more visually interesting



Every decision should improve the user's likelihood of saying:



"That's exactly the word."

16\. Code Standards



Every function should do one thing.



Keep components small.



Prefer composition.



Avoid giant files.



Avoid deeply nested logic.



Document non-obvious code.



17\. Product Principles



When making decisions:



Simplicity wins.

Speed wins.

Precision wins.

Clarity wins.

Less UI is better.

Faster answers are better.

If the feature doesn't increase



"That's it."



don't build it.



18\. Future Vision (Not MVP)



Possible future features:



multiple languages

phrase finder

idiom finder

slang

legal terminology

medical terminology

historical language

API

browser extension

writing integrations



These are explicitly outside the MVP.



19\. Final Statement



Every search should attempt to recreate the experience of talking to a brilliant friend who instantly says:



"I think the word you're looking for is..."
